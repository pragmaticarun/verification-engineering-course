# From the article to the course

The source is the X article by @0xarcos, posted 18 November 2026: [status 2123038548580245659](https://x.com/0xarcos/status/2123038548580245659). It is a field manual for a harness: a `CLAUDE.md`, a verify skill, a checks file, a stop hook, and a commit hook. The question it asks is the right question. Done is a claim, and a check the change can edit is a suggestion.

This course does not reprint the article. The table says what we kept and what we replaced. Verdicts on the article's factual claims are on the [claim check](claims.md).

| Module | Article sections it draws on | What we keep | What we change |
| --- | --- | --- | --- |
| [1](m01-why-verification/index.md) | Intro, the 30-second version, "done is a claim" | A person reads evidence. A tick is not a run. | Drop the salary and the "30 agents" framing. The timeline does not fit the public Fable 5.2 date unless you assume unstated early access. Ground the argument in Anthropic's review note and in Karpathy on verifiability, and compute the throughput instead of asserting it. |
| [2](m02-defining-done/index.md) | The call to define done, and the warning about a vague goal | Done has to be something a program can fail. | The article never shows a brief. We add a template with an acceptance command, non-goals, and allowed files. The allowed-file list is the scope check the article's table promised and its code did not implement. |
| [3](m03-instructions-permissions/index.md) | The first two setup steps, `CLAUDE.md` and a skill | A short rule file, and a verify skill you run before you stop. | The article is Claude-only. We add `AGENTS.md` (Codex walks from the repo root and stops at 32 KiB) and a Cursor rule. We separate instructions from permissions from hooks, and we note that a repo skill named `verify` replaces the bundled one. |
| [4](m04-hooks-gates/index.md) | Stop hook, commit hook, off / observe / enforce | A stop hook, a commit hook, and a mode you can roll out. | Session-scoped rounds, `stop_hook_active`, the eight-continuation cap, an exemption that must be a real trailer with a reason, locks on settings and the gate file, a tree hash instead of mtime, and unit tests on recorded events. |
| [5](m05-fast-layers/index.md) | The flaky-test policy | No sleeps, no retry-until-green. | Coming soon. Types, linters, snapshots, and contract tests, which the article skips. |
| [6](m06-cant-fool-tests/index.md) | No-op tests, property tests, differential tests | Properties and a second implementation. | Coming soon. Property tests do not by themselves kill a no-op test, because the agent writes the generator too. Mutation testing is the direct check. The article's "balance stays non-negative" example never withdraws. Module 4's lab already replaces it with one that does. |
| [7](m07-native-formal/index.md) | The Lean verification aside | Formal checks are becoming practical for a working engineer. | Coming soon. The model in that work was Opus 5.5, and the proof was Lean and TLA+ of a model. We add sanitizers, Miri, Kani, and a performance budget, which a media library actually needs. |
| [8](m08-run-and-prove/index.md) | The verify skill, `evidence.md`, the stamp | An evidence file, a NOT CHECKED line, a stamp on the commit. | Coming soon. The runner produces the evidence and CI recomputes it. The agent does not type PASS. This milestone's runner already does the important half, and module 8 will bind it to end-to-end audio. |
| [9](m09-reward-hacking/index.md) | The seven fakes, "a check the change can edit" | The judge has to live where the diff cannot quietly change it. | Coming soon as a full module. The local hook is not that place. CODEOWNERS, a ruleset, required checks, and a tamper scan are. The template is already in `harness/.github/`. |
| [10](m10-agents-verifying-agents/index.md) | One reviewer, a rubric, facts before the verdict | One reviewer with a rubric, observations before the score. | Coming soon. Add a way to measure the reviewer: known incidents, clean merges, and a split between the set you tune on and the set you report. |
| [11](m11-orchestration/index.md) | "One worktree, one session" | Isolation per agent. | Coming soon. The article gives the idea a sentence. The module has to cover worktrees, headless runs, merge queues, and the fact that a green review of a stale commit is about the old tree. |
| [12](m12-metrics-ratchet/index.md) | Reads per ship, escapes, "every miss becomes a check" | Count what escaped and what a person still had to open. | Coming soon. Add cost, latency, false blocks, and catch rate. Do not auto-delete a check because it has been quiet for 60 days. Rare checks are sometimes the catastrophic ones. |
| [Capstone](capstone/index.md) | The one-evening checklist | Start in observe, then enforce, with a written list. | Coming soon. Replace the evening checklist with a before/after measurement on parallel mocked agents. |

The ten defects the article's own sketches leave open are exercised in [module 4](m04-hooks-gates/index.md). Each one has a recorded scenario CI runs.
