# From the article to the course

The source is the X article by @0xarcos, posted 18 November 2026: [status 2123038548580245659](https://x.com/0xarcos/status/2123038548580245659). It is a field manual for a harness: a `CLAUDE.md`, a verify skill, a checks file, a stop hook, and a commit hook. The question it asks is the right question. Done is a claim, and a check the change can edit is a suggestion.

This course does not reprint the article. The table says what we kept and what we replaced. Verdicts on the article's factual claims are on the [claim check](claims.md).

| Module | Article sections it draws on | What we keep | What we change |
| --- | --- | --- | --- |
| [1](m01-why-verification/index.md) | Intro, the 30-second version, "done is a claim" | A person reads evidence. A tick is not a run. | Drop the salary and the "30 agents" framing. The timeline does not fit the public Fable 5.2 date unless you assume unstated early access. Ground the argument in Anthropic's review note and in Karpathy on verifiability, and compute the throughput instead of asserting it. |
| [2](m02-defining-done/index.md) | The call to define done, and the warning about a vague goal | Done has to be something a program can fail. | The article never shows a brief. We add a template with an acceptance command, non-goals, and allowed files. The allowed-file list is the scope check the article's table promised and its code did not implement. |
| [3](m03-instructions-permissions/index.md) | The first two setup steps, `CLAUDE.md` and a skill | A short rule file, and a verify skill you run before you stop. | The article is Claude-only. We add `AGENTS.md` (Codex walks from the repo root and stops at 32 KiB) and a Cursor rule. We separate instructions from permissions from hooks, and we note that a repo skill named `verify` replaces the bundled one. |
| [4](m04-hooks-gates/index.md) | Stop hook, commit hook, off / observe / enforce | A stop hook, a commit hook, and a mode you can roll out. | Session-scoped rounds, `stop_hook_active`, the eight-continuation cap, an exemption that must be a real trailer with a reason, locks on settings and the gate file, a tree hash instead of mtime, and unit tests on recorded events. |
| [5](m05-fast-layers/index.md) | The flaky-test policy | No sleeps, no retry-until-green. | Types, linters, and the C ABI in one fast tier. insta and nextest are cited and not installed. The article skips this layer. |
| [6](m06-cant-fool-tests/index.md) | No-op tests, property tests, differential tests | Properties and a second implementation. | Property tests do not by themselves kill a no-op test, because the agent writes the generator too. The light job kills one hand-written mutant. The heavy job runs cargo-mutants on `clamp.rs` and a 15-second cargo-fuzz smoke. Neither is a score or a campaign. |
| [7](m07-native-formal/index.md) | The Lean verification aside | Formal checks are becoming practical for a working engineer. | The model in that work was Opus 5.5, and the proof was Lean and TLA+ of a model. We run sanitizers on the C++ consumer, one Miri test, an exhaustive i16 grid, and one Kani harness on `i8 / 16` through `clamp_unit`. That harness is not a proof about every f32. |
| [8](m08-run-and-prove/index.md) | The verify skill, `evidence.md`, the stamp | An evidence file, a NOT CHECKED line, a stamp on the commit. | The runner produces the evidence and CI recomputes it. The agent does not type PASS. `prove.py` runs `pcmx` and lists what that command did not run. |
| [9](m09-reward-hacking/index.md) | The seven fakes, "a check the change can edit" | The judge has to live where the diff cannot quietly change it. | The local hook is not that place. The corpus and the tamper scan are. CODEOWNERS and the ruleset are templates until GitHub applies them. Held-out peak cases sit outside the mock agent's tree. |
| [10](m10-agents-verifying-agents/index.md) | One reviewer, a rubric, facts before the verdict | One reviewer with a rubric, observations before the score. | The reviewer is a script. Precision and recall are the report split only. The tune split is counted and excluded. No model is called. |
| [11](m11-orchestration/index.md) | "One worktree, one session" | Isolation per agent. | Six real git worktrees, a stale review refused, a stale base refused, a budget of eight. Headless, cloud, and the merge queue are cited and not started. |
| [12](m12-metrics-ratchet/index.md) | Reads per ship, escapes, "every miss becomes a check" | Count what escaped and what a person still had to open. | The report adds cost, latency, false holds, and catch rate, from a twelve-row fixture. A quiet catastrophic check is not deleted. Sixty days stays the author's number. |
| [Capstone](capstone/index.md) | The one-evening checklist | Start in observe, then enforce, with a written list. | The same eight mocked changes, shipped by tick count and by exit code. Escapes go from 3 to 0 on that fixture. It is not a live fleet. |

The ten defects the article's own sketches leave open are exercised in [module 4](m04-hooks-gates/index.md). Each one has a recorded scenario CI runs.
